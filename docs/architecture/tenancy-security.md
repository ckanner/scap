# 租户、资源与安全边界

状态：2026-11-02 已实现静态多库凭据绑定、逐操作 cell 授权复核、SQL 准入和有界资源；外部身份源、动态租户目录、公平调度与独立租户进程仍为 planned。当前服务配置与限制见 [SQLite 服务实现](../engineering/sqlite-service.md)。每库一个文件不构成独立安全沙箱；多个库仍共享进程、cell 与持久介质故障域。

2026-11-04 已增加按需创建的每库 SQL lane、每库请求额度与 peer 连接复用，见 [ADR-0015](../adr/0015-incremental-blocks-and-isolated-execution.md)。这没有增加跨库权限，也未实现租户间的加权公平调度或独立进程隔离。

## 1. 身份和权限

- 当前 JSON 配置保存 token 的 SHA-256 摘要，绑定路由名、不可变 `db_id` / incarnation / placement、principal、credential、权限及 auth_epoch。入口从 Bearer 凭据映射这些值，不信任客户端自报的内部 Admission。
- 正式 gateway/worker 集成在 daemon；读写、原结果查询和 status 都重新检查 cell 的当前身份、auth_epoch 和主体权限。结果查证还绑定原请求主体与 fingerprint，知道 request ID 不授予读取他人结果的权限。
- 数据库显示名称、Host header、URL 路径只参与寻址，不能单独授予访问权。
- 服务管理权限与业务 SQL 权限分离。自动 Claim/Activate/归档使用服务上下文；业务操作继续使用原调用者 Admission，冷唤醒前先复核调用者。不能把服务 ADMIN 权限借给原始 SQL 请求。
- 创建当前配置库与 owner/归档等管理操作进入 cell 的有序幂等记录；通用管理 API、动态租户目录、外部身份源、令牌到期/轮换和可靠审计平台尚未实现。
- 内部 RPC 使用 mTLS 和服务身份，不对租户开放 Raft、对象管理或节点管理接口。

原生 SQLite 文件没有替平台实现租户认证。外部用户不得取得 worker 文件系统或共享对象存储写凭据。

## 2. 权限变更与依赖失效

路由缓存和权限缓存不同：旧路由可以被 cell 拒绝并刷新；过期权限不能因为“请求到了正确节点”就继续使用。

当前 token 表是进程启动时的静态配置，不是有 TTL 的外部策略缓存，也没有 JWT 验签或自动到期。`AuthFence` 已在 cell 状态机实现，旧配置中的 auth_epoch 会被当前权威拒绝；服务不会自动把旧凭据升级到新 epoch。尚无外部授权管理接口或配置热更新，修改配置文件也不等于复制状态中的策略已经变更。没有 quorum 时无法获得新的强读授权，不能无限沿用旧 view。

后续接入外部策略源时，初始设计采用最长 **60 秒**的正向权限缓存，且不晚于 token 到期；缓存命中不延长有效期。以下是 planned 合同，不能当作当前静态 token 已有的过期或吊销分发能力：

- 权限服务暂时不可用时，仅在已有授权证明仍有效的窗口内继续受限数据访问。
- 到期后拒绝新的受保护操作，包括已有连接的新语句或提交；不无限延长旧 token 或缓存。
- 新租户、新凭证、权限变更和管理操作在无法验证时 fail closed。
- 每库紧急撤销通过 cell 上有序的权限版本或 fencing 变化阻止后续请求 / 提交。其生效依赖 cell quorum。
- 全域即时撤销依赖所有相关控制和数据域，网络分区时不能承诺立即到达全部节点；已运行查询与已提交事务按既定语义处理。

权限版本变化不能通过可延迟的 etcd watch 被当作立即生效；状态机校验和权限新鲜度策略共同构成边界。

## 3. SQL 能力限制

正式 adapter 已支持受控 SQL 子集，使用 SQLite authorizer、连接配置和平台策略限制高风险或破坏存储协议的能力；完整允许/拒绝范围见 [引擎合同](../engineering/sqlite-engine.md)和 [HTTP 子集](../../crates/scap-service/README.md)：

- 默认禁止跨数据库 `ATTACH`，避免绕过租户边界和宣称不存在的跨库原子事务。
- 禁止租户动态加载 native extension 或任意本地文件访问。
- 对改变 journal、synchronous、page size、checkpoint、数据库路径或共享内存行为的 PRAGMA 建立明确允许列表。
- UDF / 向量扩展等只能由平台按版本装配、隔离并验证；不能允许非确定外部副作用逃出事务恢复模型。
- 当前恢复只接受固定 page size、完整身份与历史摘要验证后的内部镜像；任意客户文件导入 API 未开放。未来导入须检查大小、格式、page size、引擎支持及一致性，不能失败后尝试未知模式上线。

SQL 参数仍应由应用绑定。平台日志默认不保存 SQL 参数和数据行；诊断采集须限时、限权限并脱敏。

## 4. 资源隔离

| 资源 | 当前已实现 | 后续要求 |
| --- | --- | --- |
| CPU / 查询 | 按需创建每库串行 lane，活动/退出中合计最多 32 个；执行预算/取消 | 加权公平调度、CPU 配额 |
| SQL 准入 | 全局 32 个请求 / 8 MiB，每库 8 个请求 / 2 MiB；排队和执行共同计量 | 每租户速率、独立资源池与动态预算 |
| 内存 / 缓存 | 静态最多 32 库，单库逻辑镜像 256 KiB，SQL 参数/结果/暂存均有上限 | 更大 profile、租户独立缓存和压力治理 |
| 文件与磁盘 | 私有新缓存目录、路径准入与有界登记；RocksDB 错误 fail closed | 磁盘水位控制、恢复/控制记录预留、cgroup/容器隔离 |
| 提交 | 每库单 writer，command/state 上限，accepted/cancel 及管理记录到限拒绝 | 每租户速率、公平带宽与可证明的历史压缩 |
| 连接 / 会话 | HTTP/peer 分别限额，原绝对 deadline；HTTP/1 每请求关闭，peer 复用有界连接并逐 RPC 复核证书与当前 policy | SQL HTTP 连接复用和交互式事务 |
| 冷恢复 | 精确对象、大小/hash 校验、原 deadline；前景仅占该库 lane，冷库空闲时无专用线程 | 独立恢复优先级、带宽公平与恢复容量预留 |
| 对象存储 | 一个后台线程、任务与完成各 8 槽、单库单 pending、失败退避 | 安全 GC、保留与 pin 退休协议、分块/增量对象 |

共享 worker 内的多个 SQLite 库共享进程故障边界；进程崩溃可能同时影响这些库。需要更强隔离的客户使用独立进程或资源池，并对宿主资源设置 cgroup / 容器限额。

每个 lane 使用只含本库的不可变配置，原调用者 Admission 与逐操作权威检查继续生效；不能因为共享 dispatcher 或归档服务而借用其他库的凭据。不同库可并行执行，前景 hydrate 的对象 I/O 不持有后台任务队列锁。每库额度使单个阻塞库不能独自占满全局请求预算，但全部库仍共享线程上限、cell、CPU 和持久介质。

dispatcher 的目录轮询仍同步执行元数据检查与维护，活动 lane 也定期维护；这些等待可能推迟分发。当前配额不是加权公平调度，不保证所有并发租户的尾延迟或恢复带宽。热点库独立 cell/worker、多 cell 自动迁移尚未实现，不能把共享资源预算描述为每租户独占额度。

## 5. 数据保护与密钥

- 当前 peer RPC 使用 mTLS、scope 与实际叶证书 pin。SQL HTTP 默认只允许 loopback；非 loopback 需 `proxy_terminates_tls=true` 明示外部 HTTPS 终止，开关本身不提供加密。外部 TLS/LB、证书签发分发及自动轮换仍需生产部署设计，不能直接把无 TLS 的入口暴露给租户。
- S3 默认要求 HTTPS，明示 endpoint/bucket/region 和指定凭据变量；不隐式读取任意 ambient 云身份。S3 和磁盘的静态加密/KMS 集成属于部署与后续功能要求，当前对象摘要不表示已完成加密。
- 对象摘要用于检测损坏，不替代访问控制或加密认证。
- 密钥、token、数据库内容、真实客户日志不得提交到 Git 仓库。
- 密钥不可用时，不能将无法解密的数据当作空数据库。已解密热数据能否继续服务由密钥缓存与吊销策略决定，冷恢复依赖不能被隐藏。
- 恢复备份必须覆盖加密元数据引用，并验证灾难环境仍可取到正确密钥；备份密钥本身采用独立访问控制。

## 6. 控制面和日志信息

当前 live/ready 与数据 API 分离；数据库 status 必须经当前 READ 授权和 ReadIndex，只返回 revision、suspended、cold、owner_active、archived_revision，不返回对象 key 或整个 cell。公开健康检查不提供这些租户数据，也不作为提交成功证明。通用管理和调试 API 尚未开放。

Metrics 使用有界标签，禁止将所有数据库 ID 或 SQL 文本作为无限 cardinality 标签。按库排障走受控查询、日志或采样 trace。

完整审计平台须覆盖权限变化、owner 变更、删除、恢复、迁移、成员变更和灾难恢复；当前 cell 管理幂等记录不等于可运营的全量审计系统。审计出口故障的缓存与阻塞策略另行定义，不能因为监控不通就改变数据提交持久性。

## 7. 恢复不是授权复制

当前 `HydrateArchive` 仅补回当前已发布归档覆盖的物理字节，逐条核对保留的 receipt、结果和身份，不能将旧归档中的权限覆盖当前 cell 状态。Prune 保留当前授权与全部结果；对象永久保留且没有 GC，不允许仅依据旧 Cold 标签或 bucket 列表选择恢复源。

PITR / fork 恢复到新数据库身份时重新分配权限，不能自动把历史 token 重新激活。删除后的旧凭据、旧请求 ID 和旧本地文件不能访问同名新库。

PITR/fork/删除/新身份恢复为 planned；当前常规重启恢复的是相同已确认历史。SQLite cache 缺失/内容损坏从权威重建，RocksDB 权威状态坏/丢则拒绝 OpenExisting，不能初始化同身份空库绕过权限与历史。

安全漏洞报告和修复协作见 [SECURITY.md](../../SECURITY.md)。
