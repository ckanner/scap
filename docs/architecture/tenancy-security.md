# 租户、资源与安全边界

状态：拟实现要求。目标是可验证的数据库隔离和资源治理，不把“每库一个文件”视为独立安全沙箱。

## 1. 身份和权限

- 数据访问凭据绑定 tenant、不可变 `db_id`、incarnation、角色、到期时间和权限版本。
- Gateway 和 worker 都验证数据库身份；cell 命令验证当前数据库实例和提交权限状态。
- 数据库显示名称、Host header、URL 路径只参与寻址，不能单独授予访问权。
- 管理权限与业务 SQL 权限分离；创建、迁移、恢复、删除、权限变更都有独立审计记录。
- 内部 RPC 使用 mTLS 和服务身份，不对租户开放 Raft、对象管理或节点管理接口。

原生 SQLite 文件没有替平台实现租户认证。外部用户不得取得 worker 文件系统或共享对象存储写凭据。

## 2. 权限变更与依赖失效

路由缓存和权限缓存不同：旧路由可以被 cell 拒绝并刷新；过期权限不能因为“请求到了正确节点”就继续使用。

初始设计采用最长 **60 秒**的正向权限缓存，且不晚于 token 到期；缓存命中不延长有效期。这个数值是待验证的配置目标，不是已经实现的安全承诺。

- 权限服务暂时不可用时，仅在已有授权证明仍有效的窗口内继续受限数据访问。
- 到期后拒绝新的受保护操作，包括已有连接的新语句或提交；不无限延长旧 token 或缓存。
- 新租户、新凭证、权限变更和管理操作在无法验证时 fail closed。
- 每库紧急撤销通过 cell 上有序的权限版本或 fencing 变化阻止后续请求 / 提交。其生效依赖 cell quorum。
- 全域即时撤销依赖所有相关控制和数据域，网络分区时不能承诺立即到达全部节点；已运行查询与已提交事务按既定语义处理。

权限版本变化不能通过可延迟的 etcd watch 被当作立即生效；状态机校验和权限新鲜度策略共同构成边界。

## 3. SQL 能力限制

首次支持受控 SQL 子集，使用 SQLite authorizer、连接配置和平台策略限制高风险或破坏存储协议的能力：

- 默认禁止跨数据库 `ATTACH`，避免绕过租户边界和宣称不存在的跨库原子事务。
- 禁止租户动态加载 native extension 或任意本地文件访问。
- 对改变 journal、synchronous、page size、checkpoint、数据库路径或共享内存行为的 PRAGMA 建立明确允许列表。
- UDF / 向量扩展等只能由平台按版本装配、隔离并验证；不能允许非确定外部副作用逃出事务恢复模型。
- 数据库文件导入必须检查大小、格式、page size、引擎支持及一致性；导入失败不自动尝试未知模式上线。

SQL 参数仍应由应用绑定。平台日志默认不保存 SQL 参数和数据行；诊断采集须限时、限权限并脱敏。

## 4. 资源隔离

| 资源 | 约束方向 |
| --- | --- |
| CPU / 查询 | SQL 时间限制、progress/interrupt、有界执行池、租户公平队列 |
| 内存 / 缓存 | 每库及每 worker 预算、输出大小、事务暂存大小、数据库打开数 |
| 文件与磁盘 | fd 限制、恢复目录预算、磁盘水位、临时文件上限 |
| 提交 | 每库在途写、每租户速率、cell 总字节预算、大事务拒绝 |
| 连接 / 会话 | 连接数、事务持续时间、空闲会话和会话固定路由 |
| 冷恢复 | 每租户 / cell / 节点并发，下载带宽与解压限制 |
| 对象存储 | 上传/读取并发、请求预算、压缩和保留策略 |

共享 worker 内的多个 SQLite 库共享进程故障边界；进程崩溃可能同时影响这些库。需要更强隔离的客户使用独立进程或资源池，并对宿主资源设置 cgroup / 容器限额。

单库单写者不等于全平台单写者；不同库可并行。单个热点数据库应迁入独立 cell / worker，避免其大事务、归档积压或恢复操作拖慢所有客户。

## 5. 数据保护与密钥

- 外部连接使用 TLS，内部采用 mTLS；证书自动轮换过程必须测试长连接和故障场景。
- S3 与持久日志使用适当的静态加密；采用云 KMS / 等效密钥服务时，恢复依赖密钥可用性。
- 对象摘要用于检测损坏，不替代访问控制或加密认证。
- 密钥、token、数据库内容、真实客户日志不得提交到 Git 仓库。
- 密钥不可用时，不能将无法解密的数据当作空数据库。已解密热数据能否继续服务由密钥缓存与吊销策略决定，冷恢复依赖不能被隐藏。
- 恢复备份必须覆盖加密元数据引用，并验证灾难环境仍可取到正确密钥；备份密钥本身采用独立访问控制。

## 6. 控制面和日志信息

控制 API、数据 API、健康检查与调试接口分离。公开健康检查不包含对象键、token、完整 SQL、客户身份或内部成员地址。

Metrics 使用有界标签，禁止将所有数据库 ID 或 SQL 文本作为无限 cardinality 标签。按库排障走受控查询、日志或采样 trace。

审计记录至少覆盖权限变化、owner 变更、删除、恢复、迁移、成员变更和灾难恢复。审计出口故障的缓存与阻塞策略单独定义；不能因为监控不通就改变数据提交持久性。

## 7. 恢复不是授权复制

PITR / fork 恢复到新数据库身份时重新分配权限，不能自动把历史 token 重新激活。删除后的旧凭据、旧请求 ID 和旧本地文件不能访问同名新库。

安全漏洞报告和修复协作见 [SECURITY.md](../../SECURITY.md)。
