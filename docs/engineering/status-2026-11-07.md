## 初始审查发现的存储误配置缺口（已由 #28 修复）

以下是基线 `e2c44b0` 的历史发现；后续防护及实际验证见本文“新候选本地验收完成”。当时主线已经创建独占私有镜像，禁止继承旧数据库文件和 sidecar，并通过对象 API 发布数据；它不共享同一 WAL。主线的服务配置只检查缓存目录绝对且存在，原生镜像构造也未检查文件系统类型。因此仍可能把运行时执行文件误放 NFS/EFS/FUSE。

本批候选增加：

- Linux 的描述符文件系统类型检查；未知或未支持类型失败关闭。
- 服务配置及直接 Engine 构造前的检查。
- 原生 ImageBuilder 的父目录和新私有目录检查。
- 确定性分类与 I/O 失败测试、真实目录与 symlink 路径测试，以及服务入口拒绝测试。
- [部署边界说明](../operations/sqlite-storage-safety.md)，包含 overlay 底层、独占块设备、SQLite 临时文件和受信任本地运维限制。

这属于误配置防护。它不证明所有底层文件系统栈正确，也不把 S3 CAS 变成对任意本地损坏的修复机制。
