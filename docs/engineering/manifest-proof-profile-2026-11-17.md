# Manifest 证明：减少分配，保留完整绑定

日期：2026-11-17。生产候选已提交为
[`9b5e9ae`](https://github.com/ckanner/scap/commit/9b5e9aebd61a8315c98f13d915e24367006616ec)，
基于 PR #60 的 `b25b785`。本页记录该候选的独立单元验证和有界指纹微型性能分析；
不将后续合并形成的新组合自动视为已验收。

**本次结果：**普通工作区单元 792 项全部通过、无忽略；严格 Clippy 通过。
原 HEAD 正文仍参与完整 SHA-256 校验，证明仍绑定原 context、backend、lineage、
Scope、物理世代、根、ETag 和 deadline。改动减少内部表示的分配，不改变持久格式、
S3 条件发布、原始结果或 ACK 顺序。原先四库写入约 24% 的回退仍未完成因果定位，
本次不宣称已经消除。历史配对结果继续见[原性能验收](verified-manifest-load-validation.md)。

## 1. 实现

| 位置 | 变化 | 保留的约束 |
| --- | --- | --- |
| `object_context.rs` | 私有 HEAD 指纹从十六进制 `String` 改成 `[u8; 32]`；保留原 JSON 缓冲区和完整 SHA-256 | 所有正文成员仍参与比较；对象 key 和持久数据中的十六进制 hash 格式不变 |
| `data_tree.rs` | 证明借用原输入根；无页变化时输出根用 `Cow::Borrowed`，变化后的根继续拥有其字符串 | 借用期间原根不能修改；proof 仍不可克隆，只能在原操作内消费 |
| 单元验证 | 保留原跨 context／backend／根／期限／健康／CAS 反例，新增完整正文指纹等价检查 | 普通单元没有忽略项；只增加测试文件清单，不排除生产代码 |

新增等价检查覆盖小型 HEAD、达到 1,024 个权限主体的 HEAD、包含转义与中文标签的
保留快照，以及权限、保留结果计数、owner 和权限世代的正文变化。

取消十六进制表示和根复制是源码层面的分配减少；未用 allocator 采样测量每事务总分配，
也未据此推算 RSS 或生产吞吐。

## 3. 有界指纹分析

计时夹具在临时副本中编译为测试模块，直接调用真实私有产品函数；没有把计时测试
加入普通单元门禁。可复现夹具与步骤见[实验目录](../../experiments/head-fingerprint/README.md)。

每个输入运行九轮，轮换三种实现的执行顺序；每轮小 HEAD 各 20,000 次，大 HEAD
各 1,000 次。记录所有样本、实际正文大小、源码与可执行文件 SHA。计时前暂停本次
协作中的重构建，但未证明独占宿主资源。以下单位均为**每次指纹的墙钟纳秒中位数**：

| 运行与输入 | JSON 字节数 | 原十六进制指纹 | 保留缓冲区的二进制指纹 | 直接流入 SHA-256 |
| --- | ---: | ---: | ---: | ---: |
| 首次，小 HEAD | 745 | 907 | 868 | 801 |
| 首次，1,024 主体 | 58,975 | 62,782 | 61,636 | 64,269 |
| 独立 target，小 HEAD | 745 | 938 | 893 | 820 |
| 独立 target，1,024 主体 | 58,975 | 61,056 | 61,048 | 64,790 |

首次使用共享 target 编译后冻结的可执行文件；为排除构建复用风险，随后使用新专属
target 重建同一夹具，二进制 SHA-256 完全一致，并按相同协议再运行一次。两次结果
全部保留，没有挑选最快的一次或删掉较慢样本。

选择保留 JSON 缓冲区的二进制指纹：它以较小改动取消十六进制堆表示。小 HEAD 的
两次中位数较低，大 HEAD 的第二次差异基本为零，不能由此宣称普遍提速。直接流入
SHA-256 在小输入下更快，但两次大输入的中位数都更高，因此未应用到生产代码。

这不是每次事务的 CPU、排队或等待分解。没有测量网络、allocator、锁等待或 S3 服务
时间；不能将上述纳秒与历史代理账本的毫秒直接相减，也不能用指纹结果解释先前四库
吞吐下降。完整原始样本、命令、产物和日志 hash 见
[机器记录](../evidence/manifest-proof-profile-local-2026-11-17.json)。
