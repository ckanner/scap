## 2026-11-08 当前实施顺序

最新核对 main `9d6ac1b` 已合入 #31/#32，合并 tree 与冻结 actor 候选相同。两个增量通过必要本地门禁；原完整 validator 末项审计失败和磁盘导致的服务启动失败保留，精确修正及受影响重跑见[验收记录](catalogue-actors-validation.md)。没有将 AWS、生产 SLO 或 N1–N4 整体标记通过。

1. [全目录发现方案](../architecture/catalogue-discovery-plan.md)：有界原始 LIST/分页原语、正式全状态协调器、带当前权限及保护 cursor 的 HTTP/SDK，再运行无需预知名字/Scope 的全计算丢失恢复合同。普通在线分页不承诺跨 key 快照。
2. 自动 owner 路由与恢复协调；扩展 actor 的热点、公平性、唤醒风暴和资源压力合同，保留同库串行与控制预留。
3. [持续存储方案](../architecture/storage-reclamation-plan.md)：先分段请求索引，再独立 storage generation/head serial/pin/freeze，随后真实物理回收和显式快照/PITR。暂停 pin 未安全解除就阻止 GC，迟到 PUT 后重复 sweep；物理删除尚未开启。
4. 在真实目标后端及部署故障域上运行预先冻结的性能、恢复、成本和长运行 SLO；按既有范围另行获准后才进行非关键业务试运行。

有界 LIST 与分段索引已进入独立开发分支；开发进度不计为合入或验收。当前实现/目标/未运行项见[状态记录](status-2026-11-08.md)。
