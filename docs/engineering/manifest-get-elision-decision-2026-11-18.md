# Manifest GET 省略候选：停止采用的决策

日期：2026-11-18，America/New_York。

## 决策

后续产品继续采用 main `02476c8` 已验收的普通精确 Manifest GET、原 HEAD CAS 和
有界 idle pool 8。**不继续推进 #60 的 GET-elision 实现进入产品；该研究按未采用
候选归档，关闭 PR 不代表已经修复或通过性能验收。** 原分支、原失败、原始证据
和适用范围全部保留；GitHub 上的最终关闭状态以 PR 记录为准。

这个取舍结束的是一条候选实现路线，不改写历史事实：两组四库负载分别下降
24.00% 和 24.52%，原因仍未完成归因。旧运行没有相应 CPU / queue / native /
observer 阶段剖面，后来的新记录不能恢复当时不存在的证据。

## 依据

1. [历史配对](verified-manifest-load-validation.md)证明了固定负载中每次业务发布
   少一次 Manifest GET，但未证实稳定的端到端吞吐收益。
2. [后续冻结诊断](manifest-proof-causal-2026-11-18.md)已完成原计划全部四格。直连
   四库写为负 7.39%，代理四库写为负 1.98%；其他阶段有正有负。它们不归因旧
   24% 差异，也不为当前完整源码签发性能许可。
3. 诊断中的四库 64 次写少 64 个 GET、15,588 个 GET body 字节；PUT 工作量不变，
   总 S3 请求少 5.56%。新增指纹 CPU 差异约 0.76–0.84 ms，不能解释阶段约
   39–45 ms 的耗时差。没有依据删除身份绑定、降低同步或减少必要回读。
4. main 的恢复普通读取候选已经独立通过严格单位、真实合同和合并前后 CI。
   [连接池修复](service-hot-path-profile-2026-11-17.md)有自身确定的连接复用证据，
   继续保留；它不依赖该 proof，也不承诺所有活跃连接总数最多为 8。

因此没有继续追加短 TPS 样本或把未验证优化重新放入运行时开关。后续性能工作
针对当前完整生产路径，优先实测原始业务可以表达的 SQL batch，并补足持续到达、
过载拒绝、两租户进展和工作资源归还的合同。

## 接续实现

新 [object-overload 固定计划](../../experiments/object-overload/PLAN.md)与原历史
配对及 871 POST 基线独立。它明确：

- 64 个独立事务与 8 个八语句事务写相同 64 行；分别报告事务/s 与逻辑操作/s。
  批内多语句本身已有产品实现，本实验不将其命名为服务器 group commit。
- 原始 30 秒固定开环到达，保留全部计划、发出、拒绝、UNKNOWN、超时和生成延迟。
- 每个原 request identity 只 execute 一次，随后 lookup / cancel / lookup 查证，
  最终数据、随机原结果、完整 S3 条件与依赖回读、owned 退出逐项独立审核。
- 所有固定窗口都需有热点写、其他租户强读和控制请求的真实进展；采样指标只按
  实际观测解释，不外推为硬资源边界或生产 SLO。

新合同的工具自测、完整实际和反例控制各自记录来源；缺失实际即保持 NOT_RUN。
真实 AWS、长期 GC、默认 10 GiB 容量及生产 SLO 仍需相应独立资格验证。
